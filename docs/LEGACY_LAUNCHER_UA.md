# Ізольований запуск старих функцій

Основна точка входу проєкту — **YEBOYBot.cmd**. **[22]** відкриває legacy-меню;
те саме меню доступне подвійним кліком **run.bat**. Потрібен Python 3.12 із
Python Launcher або командою `python`. Адміністратор, Git та системний FFmpeg
для режиму без музики не потрібні. Системні компоненти автоматично не встановлюються.

1. Зупиніть Core V2 через [3], якщо використовуватимете той самий Discord token.
2. У Провіднику створіть копію `config/example_options.ini` з назвою `options.ini`,
   якщо власного файла ще немає. Збережіть потрібні старі налаштування.
3. У текстовому редакторі заповніть `[Credentials] Token` і `[Chat] CommandPrefix`.
   Токен не вводьте в CMD-команди, Git або скриншоти. `.env.v2` не переноситься.
4. Відкрийте [22] або `run.bat`, виберіть **[1] Старі команди без музики**.
   `.venv-legacy` та залежності встановлюються автоматично при потребі.
   Завантажуються Moderation, User, Help, RankCog. Це старі prefix-команди,
   а не нові Core V2 slash-команди. Довідка: `!help` / `!helpme` для префікса `!`.
5. Процес працює в цьому вікні. **Ctrl+C** зупиняє його; **[0]** виходить із меню.
   Фоновий режим, автозапуск і recovery цього старого процесу не реалізовані.

Старий клієнт використовує `Intents.all()`. У Discord Developer Portal потрібні
відповідні privileged intents, зокрема Message Content для prefix-команд.
Мінімізація intents і належна перевірка permissions/hierarchy старих команд
ще потребують окремої роботи. Рекомендується окремий тестовий сервер і token.
OS locks розрізняють legacy і Core V2, але не визначають однаковий token між ними.

Меню також має **[2]** встановити/відновити залежності, **[3]** локально перевірити
середовище без Discord login, **[4]** запустити стару музику. У [4] збережені
попередні вимоги: `E:\Discord Bot\Bot\bin\ffmpeg.exe`, `ffprobe.exe` й обидва
Spotify credentials. Ці файли не завантажуються автоматично. Старі
`nocheckcertificate=True`, переносність, правила джерел та музичні алгоритми
у цій ітерації не виправлялись; відтворення не перевірене. [1] не імпортує Music.
Довідка старого `helpme` досі містить історичний перелік, зокрема музичні команди;
фактично підключені команди дивіться через `help`.

## Межі й захист встановлення

- `run.bat` лише знаходить Python і викликає stdlib-контролер; реєстр не змінюється.
- Лише `.venv-legacy`, без system/user site-packages; запуск Python з `-I`.
  Змінні PYTHON/PIP, що можуть змінити шлях імпорту або місце встановлення,
  очищуються; proxy/CA trust зберігаються. Глобальний pip config відключається.
  Українські stdin/stdout/stderr явно UTF-8, включно з перенаправленим виводом Windows.
  Штатний каталог виконуваного CPython дозволений точно, без дозволу сторонніх підкаталогів.
- `requirements-legacy.txt` замінює встановлення історичного root requirements
  для цього входу. Старий файл збережений, але не використовується лаунчером.
  Не встановлюйте root requirements вручну в Core V2.
- Використовується `discord.py[voice] 2.7.1`: активні legacy setup очікують
  асинхронний `add_cog`, якого немає у pinned `py-cord 2.6.1`.
  Pillow, spotipy, yt-dlp та ConfigUpdater покривають імпорти активних cogs/helpers.
  Зайві desktop/web/scientific пакети не встановлюються. Це окреме середовище,
  навіть попри спільний дистрибутив discord.py із Core V2.
- Немає global uninstall, cache purge або break-system-packages; pip працює
  з `--require-virtualenv`, `--isolated`, `--no-cache-dir`, лише binary wheels.
  Повторний запуск звіряє SHA вимог, pinned версії й критичні імпорти.
  Це перевірка сумісності, а не CVE-аудит чи криптографічний lock усіх transitives.
- Виявлені py-cord, зовнішні шляхи `.pth`, system-site-packages та посилання
  `.venv-legacy` відхиляються. Ізоляція venv не є sandbox для недовіреного коду.
- OS locks перешкоджають подвійним legacy-запускам і встановленню пакетів під час
  роботи legacy-бота. Сторонні Python-процеси не завершуються.
- Невідоме неповне середовище не видаляється: перейменуйте його для збереження,
  потім повторіть [2]. Збій pip не ставить success marker, повтор [2] дозволений.
  За змішаного середовища також збережіть стару папку перейменуванням.
- Сирі помилки pip/config/Discord не виводяться. Журнали `logs/legacy/bot.log`
  та `errors.log` дописуються; значення Credentials приховуються в logging,
  включно з traceback. Старі журнали не очищуються. Логи не ротуються автоматично;
  контролюйте розмір і не публікуйте приватні дані серверів.

Коди: 0 — виконано, 1 — помилка, 130 — переривання/EOF. При роботі з меню
показується код дочірнього бота; саме меню залишається доступним. Місцевий [3]
не підтверджує Discord ready. Перше встановлення потребує мережі до PyPI;
помилка мережі/сертифікатів не змінює системні пакети.

## Перевірка розробником

`python -I tools/legacy_launcher.py --install` і повтор тієї ж команди перевіряють
встановлення без login; `--check` — версії/ізоляцію/імпорти. Далі інтерпретатором
`.venv-legacy` виконайте `-I tools/check_legacy_cogs.py`: джерела копіюються
в тимчасовий каталог без конфігурації/даних, справжні cogs додаються і закриваються
без мережевого запуску. Відсутні assets перевіряють резервний фон/шрифт.

CI містить окреме встановлення legacy на Windows/Linux, offline cogs smoke
та legacy regression tests (pytest встановлюється лише для CI в legacy venv);
основні tests містять негативні сценарії, locks, шляхи з пробілами/кирилицею
і нативні CMD тести. Фактичні результати й ручні обмеження — у
[CORE_V2_STATUS_UA.md](CORE_V2_STATUS_UA.md). Початковий небезпечний run.bat
під час перевірок не виконувався.
