# YEBOYBot на чистому Windows-ПК

Основний сценарій: розпакувати проєкт → відкрити `YEBOYBot.cmd` → вибрати
встановлення → налаштувати Discord → запустити бота. Команди Python, pip
і ручна активація середовища для цього не потрібні.

Підтримуваний сценарій інсталятора — Windows 10/11 x64, вбудований Windows
PowerShell 5.1, доступ до інтернету й папка проєкту з правом запису. Для
автоматичного встановлення відсутнього Python потрібен Microsoft App Installer
з WinGet. Правила організації можуть забороняти запуск скриптів або встановлення
програм; панель повідомляє про таку відмову й не показує хибне «Готово».

## Перше відкриття

1. Завантажте [ZIP гілки improvement/probot-readiness](https://github.com/VolshebniKGG/YEBOYBot/archive/refs/heads/improvement/probot-readiness.zip).
2. Розпакуйте весь архів. Не запускайте CMD усередині ZIP і не копіюйте лише
   один файл: потрібні папки `tools` та `core_v2` й інші файли проєкту.
3. Двічі натисніть `YEBOYBot.cmd`. Стартова панель відкривається без Python:

   ```text
   YEBOYBot — ПОЧАТКОВЕ ВСТАНОВЛЕННЯ
   [1] Перевірити й встановити потрібне для Core V2
   [0] Вихід
   ```

4. Прочитайте пояснення й виберіть **[1]**. **До будь-яких завантажень**
   майстер перевірить комплектність основних файлів ZIP. Якщо якихось файлів немає,
   покаже їхні відносні шляхи та зупиниться, не встановлюючи Python або FFmpeg.
   Цей вибір дозволяє встановити відсутній Python 3.12 x64 для поточного
   користувача через офіційний каталог WinGet з погодженням умов Python і каталогу.
   **[0]** або Enter закриває панель.
5. Після перевірки системного Python інсталятор перевіряє FFmpeg і Deno:
   показує їхні версії й повні шляхи в разі виявлення сумісних копій.
   Для кожної сумісної програми виберіть **[1] ТАК** — використовувати з ПК,
   або **[2] НІ** — підготувати окрему перевірену копію в `bin`.
   **[0]** або Enter скасовує встановлення до етапу Python-бібліотек.
   Якщо сумісної копії не знайдено, підготовляється локальна.
6. Дочекайтеся чотирьох етапів та фінальної перевірки. Після успіху
   відкриється головне меню керування ботом.

Якщо Python уже є, інсталятор спершу перевіряє сумісну версію й використовує її.
Звичайний пошук Python не дозволяє Python Launcher/Install Manager автоматично
встановлювати runtime: дозвіл на системну інсталяцію діє лише після вибору **[1]**.

## Що робить пункт встановлення

| Етап | Фактична дія |
|---|---|
| 1/4 | Знаходить Python 3.12 x64; за відсутності й після [1] використовує WinGet. Перевіряє доступні FFmpeg та Deno й запитує вибір |
| 2/4 | Створює/перевіряє ізольовану `.venv-v2`, підтверджує pip 26.2 та встановлює потрібні бібліотеки Core |
| 3/4 | Використовує вибрані системні FFmpeg/Deno або перевірені локальні програми; лише за потреби завантажує архіви |
| 4/4 | Перевіряє бібліотеки, FFmpeg і JavaScript runtime та показує готовність |

WinGet викликається з точним ID `Python.Python.3.12`, джерелом `winget`,
архітектурою `x64` та встановленням для поточного користувача. Перевірку hash
інсталятора не вимкнено. Неперевірені EXE зі сторонніх сайтів не завантажуються.
Скрипт не запитує підвищення прав адміністратора й не змінює постійні правила
виконання PowerShell. Якщо Windows вимагає інші права або блокує дію, вона
позначається незавершеною.

Після встановлення Python повторно шукається також через реєстрацію Python
і типовий каталог користувача: поточне CMD може ще не бачити нового PATH.
Панель не покладається лише на оновлення PATH.

Бібліотеки беруться з `core_v2/requirements.txt` і встановлюються в `.venv-v2`.
**Глобальні Python-бібліотеки повторно не використовуються:** їх версії можуть
конфліктувати з Discord SDK. Наявний сумісний Python використовується як
інтерпретатор для створення цієї ізольованої папки, без перевстановлення Python.
Якщо Python відсутній, він ставиться через WinGet **для користувача Windows**,
а не як портативний Python у `bin` (штатний embedded Python не містить повного
підтримуваного механізму pip/venv).

Сумісними в цьому режимі вважаються **FFmpeg ≥9.0.2** та **Deno ≥2.9.8**
з підтвердженим запуском і відповіддю на запит версії. Перевіряються PATH
та типові місця інсталяції, але не сканується весь диск. Для обраних зовнішніх
копій `FFMPEG_PATH` та `DENO_PATH` записуються у наявну `.env.v2`.
Для локальних копій використовуються відносні шляхи `bin/ffmpeg/ffmpeg.exe`
та `bin/deno/deno.exe`. Бібліотеки продовжують працювати в `.venv-v2`;
жодних глобальних програм не видаляють. Наступна підготовка повторно
використовує вибрані й перевірені програми. Змінні середовища Windows
`FFMPEG_PATH`/`DENO_PATH`, якщо вони явно встановлені, мають пріоритет.

Історичний кореневий `requirements.txt` не використовується. Наявні інші
налаштування, токени, БД і резервні копії зберігаються. Якщо `.env.v2` відсутній,
bootstrap готує його з публічного шаблону без робочого токена.

«Готово» підтверджує Python, ізольовані бібліотеки та вибрані FFmpeg/Deno. Готовність Discord
підтверджується окремо після введення токена й фактичного підключення клієнта.

## Звіт, якщо вікно закрилося або помилка невідома

При невдалому **першому встановленні через `YEBOYBot.cmd → [1]`** панель
автоматично записує `data/v2/launcher-report.json`. Він містить тільки час UTC,
завершений код процесу й один із фіксованих етапів:
`source-bundle`, `python`, `media-probe`, `bootstrap`, `media`, `readiness`.
Крім того, поле `matched_security_events` містить лише перевірені
ідентифікатори недавніх подій блокування (якщо вони виявлені).
Вміст конфігурацій, токени, шлях профілю Windows, вивід pip, повідомлення
з журналу подій і адреси URL в цей звіт не записуються.

Якщо збій стався на `bootstrap` (Python/pip/.venv-v2), додатковий звіт
`data/v2/install-report.json` містить деталізовану безпечну категорію та
системні коди. Для діагностики достатньо скопіювати **ці два файли** після
невдалого запуску — не потрібно фотографувати консоль. Якщо їх не вдалося
створити через заборону запису, збережіть текст консолі. Звіт попередньої
спроби може залишатися після успішного запуску: звертайте увагу на
`timestamp_utc` та порівнюйте з часом помилки.

Наявні `.env.v2`, `config/options.ini`, `data` і `backups` не очищаються.
Інсталятор не встановлює програми при неповному ZIP і не обходить
контроль підпису або правила безпеки Windows.

## Одноразове налаштування Discord

У головному меню виберіть **[12] Початкове налаштування**. Уведіть токен приховано
та ID тестового сервера. Токен створюється власником у Discord Developer Portal;
інсталятор не може створити його замість вас. Не публікуйте токен у чаті чи Git.

Запросіть application на тестовий сервер з потрібними scopes і правами.
Після налаштування виберіть головний **[1] Запустити Discord-бота** й дочекайтеся
підтвердженої готовності. Подробиці Application, intents, permissions та перевірки
команд — у [Quickstart](CORE_V2_QUICKSTART_UA.md).

## Повторне встановлення й оновлення бібліотек

Справна наявна копія одразу відкриває звичайне меню, без повторного завантаження
всіх пакетів при кожному відкритті.

- **[19] Повне встановлення / відновлення Core V2** повертає початкову панель.
  Для повторної підготовки виберіть у ній **[1]**.
- **[5] Оновити Python-залежності** повторює підготовку бібліотек у наявному
  середовищі та повторно перевіряє вибрані джерела музичних програм.
  Спочатку зупиніть бота через **[3]**. Нових інтерактивних запитів тут немає.

На Windows ці дії спочатку завершують Python-процес меню. Встановлення
продовжує зовнішня панель у тому самому CMD-вікні; після перевірки меню
відкривається заново. Це дає Windows звільнити завантажені `.pyd`-бібліотеки
перед їх заміною. Працюючий бот блокує зміну свого середовища; інсталятор
не завершує сторонні процеси Python.

Службовий `install_v2.bat` також підготовлює Core, якщо Python уже встановлено.
Його неінтерактивні режими не встановлюють системний Python автоматично;
користувачеві чистого ПК слід відкривати `YEBOYBot.cmd`.

## Якщо встановлення не завершилося

| Повідомлення або умова | Що зробити |
|---|---|
| Немає WinGet/App Installer | Установіть [App Installer від Microsoft](https://apps.microsoft.com/detail/9NBLGGH4NNS1) або [Python 3.12 x64 з офіційного сайту](https://www.python.org/downloads/windows/), потім відкрийте CMD знову |
| Немає `tools/windows_setup.ps1` або `tools/launcher/bootstrap_entry.py` | Повторно розпакуйте весь ZIP у папку |
| WinGet або pip завершився помилкою | Перевірте мережу, сертифікати, App Installer, вільне місце та правила Windows; повторіть встановлення |
| `pip-upgrade` / `package-unavailable` | Версія pip існує на PyPI, але цей ПК не отримав її. Перевірте інтернет, проксі та TLS, а не перевстановлюйте Python автоматично |
| Бот ще працює | Поверніться до головного меню, зупиніть через [3] і повторіть [5] або [19] |
| Зовнішні FFmpeg/Deno зникли або змінили версію | Зупиніть бота через [3], відкрийте початковий майстер через [19] і виберіть локальні копії |
| Невідоме неповне `.venv-v2` чи зовнішні пакети | Збережіть цю папку перейменуванням і повторіть встановлення; не видаляйте власні дані |
| Після підготовки немає готовності Discord | Перевірте [12]/[11], права application й журнал [9]; успіх інсталятора не підтверджує токен |

Коли WinGet відсутній, автоматичного неперевіреного EXE-fallback немає.
Панель показує офіційні посилання. Інсталятор не обходить корпоративні правила
й не може гарантувати роботу без інтернету або за відмови Windows.

### Як читати повідомлення інсталятора

При збої консоль показує єдиний блок: **етап**, **тип помилки**, **системні коди**,
**пояснення та наступні дії**. Українська назва пояснює операцію, а позначення
в квадратних дужках допомагає зіставити її з `install-report.json`.
Код завершення процесу не є кодом WinError: наприклад, `код процесу=1`
сам по собі не встановлює причину відмови.

- `file-locked` (WinError 32/33): файл зайнятий іншим процесом; закрийте інші
  вікна бота та інсталятори, дочекайтеся завершення їхньої роботи.
- `access-denied` (WinError 5): відмовлено в доступі; це не доказ спрацювання антивіруса.
- `execution-policy` (зокрема WinError 577): політика або перевірка підпису;
  не плутати з WinError 5 і не вимикати захист.
- `environment-validation`: перевірка файлів/ізоляції; `environment-probe`:
  запуск Python. Відмова читання конфігурації зберігає системний код.

Якщо причина не визначена, інсталятор прямо це зазначає. Він не друкує сирий
вивід процесів, URL із паролями чи текст сторонніх винятків. Після відмови
в доступі, блокування файла або тайм-ауту автоматична перевстановка бібліотек
не запускається. Помилка очищення маркера не підмінює початкову причину збою.
Передавайте звіт саме останньої спроби; якщо його не вдалося записати,
попередній файл може бути застарілим — збережіть блок помилки з консолі.

### Якщо системний Python працює, але .venv-v2 відмовляє в запуску

При `stage=environment-probe`, `category=access-denied`, `WinError=5`
Windows дозволила запуск перевіреного Python 3.12, але не дозволила запуск
`.venv-v2/Scripts/python.exe`. Це **не** помилка pip і не підтвердження,
що причиною став Defender: доступ можуть заборонити NTFS, політики виконання
або сторонній захист. Не перевстановлюйте Python навмання, не вимикайте
Windows Security і не очищайте дані бота.

Початкове `YEBOYBot.cmd → [1]` тепер обмежує автоматичне відновлення:
`.venv-v2.failed-*` створюється лише за конкретної ознаки непрацездатного
посилання на Python (`broken-interpreter`), а не через невідомі помилки,
`WinError 5` або проблеми імпорту. Це зберігає первинну діагностику й не
створює повторні копії після відмови в доступі.

При свіжому `WinError 5` на етапі `environment-probe` консоль **сама**
переглядає доступні журнали CodeIntegrity (3077), AppLocker (8004) та
Defender ASR (1121), шукаючи події, пов'язані саме з `.venv-v2` Python.
До `data/v2/launcher-report.json` потрапляють **тільки коди
ідентифікованих подій**, а не сирий вміст журналів чи шляхи користувача.
Відсутність збігів не означає, що блокування не було: журнали можуть
бути недоступні, подія не обов'язково записується або причиною є
звичайні файлові дозволи. Якщо підтверджено обмежувальну політику
Windows, її слід розв'язати штатним способом; інсталятор не обходить її.

### Якщо помилка виникла на «Створення .venv-v2»

У старому bootstrap створення файлів і початкове встановлення pip виконувалися
одним викликом. Якщо Windows повертала `OSError` без текстового виводу процесу,
код втрачав `errno`/`winerror` і показував «Причину не визначено автоматично».
Це повідомлення саме по собі **не визначає причину відмови на ПК**.

Тепер послідовність така:

1. Створити ізольовану `.venv-v2` без прихованого запуску pip.
2. Окремо перевірити запуск її Python та ізоляцію пакетів.
3. Якщо pip відсутній — встановити його з комплекту Python через `ensurepip`
   без інтернету, з очищеним оточенням і обмеженим часом виконання.
4. Перевірити/оновити pip і встановити бібліотеки, як раніше.

Системні коди записуються в `data/v2/install-report.json` та виводяться в
консолі. Звіт не містить шляхів користувача, токена, URL чи сирих повідомлень pip.

| Етап / категорія | Значення й наступна дія |
|---|---|
| `venv-create` | Збій створення файлів середовища; орієнтуйтеся на числовий код і категорію |
| `environment-probe` | Файли створено, але запуск/ізоляцію Python не підтверджено |
| `ensurepip` | Запуск Python уже перевірено; збій початкового встановлення pip |
| `access-denied` | Відмова доступу або зайнятий файл; перевірте права папки, інші процеси й Журнал захисту. Не означає автоматично «антивірус» |
| `execution-policy` / `security-blocked` | Windows повідомила про заборону виконання/підпис або спрацювання захисту; перевірте відповідний журнал, для керованого ПК зверніться до адміністратора |
| `disk-full` / `path-too-long` | Звільніть місце або використайте коротший шлях до повністю розпакованого ZIP |

За блокування чи відмови доступу інсталятор **не переносить середовище й не
повторює установку навмання**. Наявне власне середовище без pip можна доповнити
після усунення причини; невідомі папки не видаляються. Не підміняйте `python.exe`,
не вимикайте захист Windows і не додавайте виключення заради встановлення.

Якщо панель ще недоступна, завантажте повний актуальний ZIP у **нову папку**,
залишивши стару папку, `.env.v2`, `data` та `backups` недоторканими.
Запустіть `YEBOYBot.cmd` → початковий `[1]`. Якщо помилка повториться,
передайте **новостворений** `data/v2/install-report.json`: старий звіт з
`pip-upgrade` не пояснює нову помилку `venv-create`.

### Якщо FFmpeg установлений WinGet, але `ffmpeg -version` не розпізнається

Після `winget install` поточне вікно PowerShell може мати застарілий
`PATH`, хоча пакет успішно встановлено. Новий `YEBOYBot.cmd → [1]`
шукає потрібний виконуваний файл також у WinGet `Packages` і `Links`,
перевіряє версію та використовує абсолютний шлях: ручне редагування
`PATH` не потрібне. За `WinError 5` під час запуску портативного
FFmpeg/Deno інтерактивний майстер може встановити офіційний WinGet-пакет
для поточного користувача й перевірити його без нового сеансу PowerShell.
Цей сценарій дозволений лише явним вибором `[1]` у початковому меню;
автоматичні ремонти не встановлюють системні пакети.

### Якщо Python намагається прочитати `python.exe` як текст

Якщо після `[2/4]` з'явилося `SyntaxError: Non-UTF-8 code ... in file ...python.exe`,
це не означає, що інтерпретатор Python пошкоджений. Старий спосіб
запуску bootstrap через PowerShell міг передавати неправильний шлях до
виконуваного скрипту. У виправленій версії інсталятор виконує
`tools/launcher/bootstrap_entry.py` через перевірений Python 3.12 x64
із прапором ізоляції `-I`, а сам модуль установки запускається з нього.

Завантажте **повний новий ZIP** із робочої гілки, розпакуйте його
в окрему папку та запустіть `YEBOYBot.cmd`. Не підміняйте окремо
`python.exe`, не вимикайте антивірус і не видаляйте `.env.v2`,
`data` чи `backups`. Сумісний Python повторно використовується.

### Якщо зупинилося на `pip-upgrade`

Якщо Windows знайшла Python 3.12 x64, але під час `[2/4]` відображено
`pip-upgrade` і `package-unavailable`, спочатку перевірте мережу.
Це повідомлення **не доводить**, що потрібної версії немає в PyPI.
На офіційному [PyPI](https://pypi.org/project/pip/26.2/) версія 26.2 існує.

1. У браузері відкрийте https://pypi.org/simple/pip/ та перевірте,
   чи немає блокування сертифіката або повідомлення мережевого фільтра.
2. У Windows PowerShell виконайте `Test-NetConnection pypi.org -Port 443`
   та `Test-NetConnection files.pythonhosted.org -Port 443`. Це перевіряє
   TCP-доступ, але **не доводить**, що pip зможе завантажити пакети.
3. Якщо діє корпоративний проксі або антивірус із HTTPS-перевіркою,
   перевірте його налаштування і довірений центр сертифікації. Не
   вимикайте перевірку TLS та не додавайте `--trusted-host`.
4. Після відновлення зв'язку відкрийте `YEBOYBot.cmd` і виберіть `[1]`.
   Наявне середовище використовується повторно; файли конфігурації та БД не видаляються.

Новий інсталятор надає пріоритет достовірним ознакам мережевої, проксі-
та сертифікатної помилки перед загальним повідомленням pip про відсутність
версії. У `data/v2/install-report.json` залишаються лише безпечні категорії:
URL, ключі, паролі та сирі журнали pip не записуються.

## Межі «встановити все»

Це всі залежності **поточної реалізації Core V2**. Для звичайного запуску зі
SQLite не потрібні Git, сервер PostgreSQL чи FFmpeg. Git потрібен окремо для
Git-оновлень; ZIP не має `.git`. PostgreSQL і його штатні інструменти потрібні
лише за вибору цієї БД. Музика й старі команди мають окреме середовище через
**[22]**, описане в [legacy-інструкції](LEGACY_LAUNCHER_UA.md).

Установлення пакетів не реалізує відсутні функції: automod, welcome, autorole,
voice XP та role panels не стають готовими від натискання кнопки. Актуальна
матриця функцій — [PROJECT_AUDIT_UA.md](PROJECT_AUDIT_UA.md).

Інструкція описує реалізований потік, а не підтверджує реальне встановлення
Python на порожній Windows-ПК, ручний Windows/logon, live Discord чи роботу
24/7. Точні автоматичні й ручні результати поточного SHA — у
[CORE_V2_STATUS_UA.md](CORE_V2_STATUS_UA.md).

### Діагностика збою початкового встановлення

Після невдалого встановлення панель завершує спробу з ненульовим кодом,
а CMD залишає повідомлення видимим. Початкове меню більше не повторюється
нескінченно. Після усунення причини відкрийте `YEBOYBot.cmd` знову.

Помилка Python-bootstrap показує етап, код завершення та категорію проблеми.
Файл `data/v2/install-report.json` містить лише безпечні технічні поля останньої
невдалої спроби: час, версію Python, платформу, етап, категорію й код.
Вивід pip, адреси проксі, токени та конфігурація до звіту не потрапляють.
Звіт не є підтвердженням поточного стану після успішного повторного запуску.

Початковий [1] повторно використовує перевірені бібліотеки. Якщо перевірка
залежностей не проходить, маркер успіху скидається й виконується одна спроба
відновлення в поточному запуску. Повторний збій завершує встановлення. Непрацездатне середовище з підтвердженим маркером
власності зберігається в `.venv-v2.failed-*` і відтворюється один раз.
Невідомі папки автоматично не видаляються. `.env.v2` та дані бота зберігаються.

Windows-сценарії перевіряються окремими тестами; запуск тестів на Linux
не підтверджує успішне встановлення на конкретному Windows-ПК.

## Музика без ручного встановлення програм

Початкове встановлення автоматично готує FFmpeg і Deno у `bin` через HTTPS
з перевіркою зафіксованих SHA-256. Перша підготовка потребує інтернету;
повторна використовує перевірені локальні файли. У новій `.env.v2` музика
увімкнена. Наявне значення `ENABLE_MUSIC` зберігається; увімкніть через [25] → [1].
Докладніше: [PORTABLE_MUSIC_UA.md](PORTABLE_MUSIC_UA.md).
