# Базова автомодерація Core V2

Модуль вимкнений за замовчуванням. Адміністратор із правом **Керувати сервером**
виконує `/automod enabled:true`; `/automod enabled:false` вимикає його.
Після оновлення потрібно опублікувати нову slash-команду через наявне меню sync
і перезапустити бота. Налаштування зберігається окремо для кожного сервера у БД.

## Правила

- Шосте та наступні повідомлення одного учасника за рухоме вікно 5 секунд
  вважаються флудом. Лічильник спільний для каналів одного сервера.
- Повідомлення з щонайменше 8 різними згаданими користувачами/ролями
  вважається масовою згадкою. Повторення тієї самої згадки не збільшує число.
- Боти, вебхуки, власник сервера й учасники з Administrator, Manage Server,
  Manage Messages або Moderate Members виключені з перевірки.
- Перевіряються лише нові повідомлення. Редагування, історія, слова, URL,
  капслок, дублікати тексту та рейди приєднань цим модулем не аналізуються.

Message Content Intent не потрібний: використовуються події та метадані згадок.
Вміст повідомлень не читається й не записується у журнал.
Модуль видаляє лише поточне виявлене повідомлення, не видає timeout або ban.
Виявлений спам не отримує текстовий XP навіть якщо видалення не вдалося.

## Дозволи та межі

Для видалення боту потрібні **View Channel** і **Manage Messages** у конкретному
каналі. Команда налаштування не надає цих прав: перевірте їх у кожному каналі.
Без потрібних дозволів повідомлення лишається, але XP за нього не видається.

Щоб не створювати лавину REST-запитів, видалення обмежені однією спробою за
секунду для користувача та однією за 0,25 секунди для сервера; водночас можуть
працювати щонайбільше 20 видалень у процесі. Частина повідомлень у сильному
флуді може залишитися. Це базовий захист, а не гарантія видалення всього спаму.
Помилка API або таймаут не запускають безмежні повтори.

Стан у пам'яті має межі: 20 000 пар сервер/учасник і 10 000 серверів;
найдавніші записи витісняються. Перезапуск скидає вікна флуду, але зберігає
налаштування в БД. Кеш налаштувань має строк життя 15 секунд; зміна через
команду в цьому процесі одразу очищає його. За недоступності налаштувань
модуль пропускає повідомлення, не застосовуючи дію навмання.

## Перевірка на тестовому сервері

1. Увімкніть модуль, переконайтеся у правах бота в тестовому каналі.
2. Звичайний учасник надсилає шість повідомлень швидше ніж за 5 секунд:
   шосте має видалитися. Модератор для цього тесту не підходить.
3. Через 5 секунд звичайне повідомлення має залишитися.
4. Вимкніть Manage Messages у бота: спам лишиться, помилка не зупинить бота.
5. Виконайте `/automod enabled:false`: нові повідомлення не видаляються.

Автоматизовані тести перевіряють межі вікна, унікальність згадок, ізоляцію
серверів, виключення, дозволи, збої API/БД, обмеження пам'яті й приватність
відповіді команди. Живий Discord потребує окремого приймального тесту.

Конкурентне читання налаштувань, яке почалося до вимкнення, може повторно
заповнити кеш старим значенням до завершення його TTL (15 с). Уже розпочате
видалення не відкочується. Миттєве припинення всіх дій не гарантується.
