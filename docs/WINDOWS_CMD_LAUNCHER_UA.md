# Керований Windows CMD запуск
Потрібен Python 3.12 з Python Launcher. Відкрийте YEBOYBot.cmd.
Віртуальне середовище .venv-v2 створює наявний install_v2.bat.
[11] запускає майстер конфігурації з прихованим введенням токена.
Впишіть DISCORD_TOKEN, TEST_GUILD_ID, SYNC_COMMANDS=test.
[1] запускає один процес із фоновими задачами. Готовність показується лише після Discord ready.
[2] виконує коректну зупинку та новий запуск; [3] зупиняє через запит із nonce.
[0] закриває меню, але залишає бот працювати. Для зупинки використовуйте [3].
Можна повторно відкрити меню; дубль блокується OS lock.
Heartbeat оновлюється щосекунди. Після 10 секунд без оновлення показується «Не відповідає».
Завислий процес автоматично не вбивається; перезапуск не запускає дубль.

[4] offline doctor, [5] залежності, [7] SQLite backup, [8] відновлення, [9] журнал, [10] перевірка БД.
[6] оновлює код із GitHub; crash-restart supervisor ще не реалізований.
Після Python-помилки виконуються до трьох повторів із паузами 2/5/15 секунд.
[3] скасовує очікування; штатне завершення та помилки конфігурації не повторюються.
Після вичерпання спроб перевірте журнал і запустіть [1].
Після kill/segfault/збою ОС потрібен ручний запуск; зовнішнього супервізора ще немає.
SQLite backup використовує DATABASE_URL зі змінних середовища або .env.v2.
PostgreSQL та in-memory SQLite у цьому меню відхиляються; для PostgreSQL потрібен pg_dump.
Windows smoke тест перевіряє меню з кириличного шляху з пробілами.
Живе Discord-підключення потребує тесту власником; без токена воно не перевірене.


## Резервування та відновлення
[7] створює перевірену копію через SQLite Backup API в backups/v2-*.db.
Копія містить дані серверів, тому зберігайте її приватно. Конфігурація й токен не додаються.
[10] перевіряє integrity_check, версію схеми v1 та потрібні таблиці/колонки без міграцій.
Для [8] спочатку зупиніть бот через [3], виберіть номер копії та введіть ВІДНОВИТИ.
Без цього підтвердження дані не змінюються.
Відновлення утримує той самий OS lock, що й бот, до завершення.
Перед зміною створюється backup поточної БД. Якщо він не створився, відновлення не починається.
Невідома схема відхиляється: автоматичного downgrade немає.
Запустіть [10], потім [1] і перевірте /status та свої дані.
Пошкоджену поточну БД спершу збережіть окремо: її неможливість резервування блокує автоматичне відновлення.
Блокування захищає процеси цього каталогу; не відкривайте ту саму БД іншими копіями бота.

Перед використанням збережіть власні зміни окремим комітом або копією; меню їх не стирає.
Пункт показує до 10 комітів та просить ввести ОНОВИТИ.
Завантажується тільки дозволена гілка. Розходження історії блокує застосування.
Якщо бот працював, він коректно зупиняється; SQLite резервується до зміни коду.
Оновлення лише fast-forward, без reset/stash, без перемикання на main.
Після оновлення requirements.txt за потреби перевстановлюються залежності у поточному venv.
Перевіряються pip check, конфігурація, підтримувана схема/ініціалізація БД та серіалізація команд
новим Python-процесом, без входу в Discord.
Раніше запущений бот запускається повторно тільки після успішних перевірок.
Знову відкрийте YEBOYBot.cmd: старе меню закривається, щоб не використовувати старі імпорти.

При невдачі бот залишається зупиненим; data/v2/update-report.json містить old/target,
етап та шлях до backup, без токенів. Автоматичного відкату коду/схеми немає.
Повернення старого коду потребує сумісної схеми або відновлення відповідної копії.
Для PostgreSQL оновлення через меню поки відхиляється до зупинки бота:
потрібен окремий перевірений pg_dump/restore workflow.
ZIP-користувачам поки потрібне ручне оновлення в окрему папку зі збереженням конфігурації та БД.

## Bootstrap першого встановлення — 25.10.2026

`YEBOYBot.cmd` шукає готове `.venv-v2`, перевіряє критичні імпорти, а за потреби
викликає `install_v2.bat`. Інсталятор шукає Python 3.12 через `py`, потім `python`.
Якщо Python відсутній, показує офіційну адресу й завершується з кодом 1;
системні компоненти автоматично не завантажує. Git не потрібен для ZIP-установки.
Bootstrap створює venv, встановлює requirements, виконує pip check та імпорти,
створює каталоги й `.env.v2`, зберігаючи наявну конфігурацію.
Повторний виклик не встановлює незмінені залежності; після збою можна повторити.
[5] відновлює залежності через той самий bootstrap. Працюючий бот або інший
інсталятор блокують зміну бібліотек через OS locks; спершу зупиніть бот через [3].
Наявний venv іншої версії Python автоматично не видаляється: після зупинки бота
перейменуйте `.venv-v2` і повторіть запуск. Дані та `.env.v2` розміщені поза venv.

Локально Linux/Python 3.12: 10 нових offline unittest пройшли; compileall успішний.
