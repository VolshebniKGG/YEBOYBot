# YEBOYBot v2 — план ядра і стан передачі роботи

Оновлено: 25.10.2026.

## Ціль
Власний універсальний Discord-бот, орієнтований за зручністю на ProBot.
Спочатку стабільне ядро й локальне тестування Windows; потім сайт налаштувань
і перенесення на сервер 24/7. Користувач дозволив змінювати репозиторій та
прибирати зайві файли. Нових дозволів на звичайні зміни не потрібно.

У попередньому робочому середовищі було створено новий проєкт YEBOYBot:
discord.py 2.7.1, AutoShardedBot, SQLite/PostgreSQL, серверна ізоляція,
атомарний XP, модераційні справи, persistent role buttons, привітання,
нагадування з lease/retry, optional music, Windows launchers, документація.

Попередній запуск повідомив: 33 pytest-тести пройдено, Ruff/compileall/pip check OK.
Це результати попередньої локальної копії, НЕ поточного GitHub-коміту.
GitHub CI, живі Discord/voice тести і PostgreSQL runtime не були підтверджені.
ZIP не був успішно збережений чи переданий користувачу.

## Поточний блокер
Середовище виконання повертає environment_offline / No usable execution environment.
Файли попереднього середовища зараз недоступні. Не стверджувати, що вони
відновлені або втрачені остаточно, без перевірки. Не позначати цей репозиторій
як завершений v2 чи як перевірений на тисячах справжніх серверів.

## Послідовність продовження
1. Відновити доступ до робочого середовища. Перевірити попередню папку YEBOYBot.
2. Якщо файлів немає — відновити код із доступного контексту, повторно перевірити.
3. Прочитати актуальний main і не затерти нові користувацькі зміни README.
4. Перевірити токени й виключити .env, data, logs, pyc, .cache з публікації.
5. Зберегти нове ядро в feature/core-v2, не видаючи старі тести за перевірку нового SHA.
6. Запустити CI Linux/Windows + PostgreSQL. Виправити всі реальні помилки.
7. Надати інструкції запуску й живого приймання на двох власних серверах.
8. Після перевірок оновити основну версію; сайт реалізовувати наступним етапом.

## Обов'язкові інваріанти ядра
- Дані сервера завжди мають guild_id; користувацькі серверні дані — (guild_id, user_id).
- Попередження, скидання, налаштування й панелі не впливають на чужий сервер.
- XP додається атомарно; перегляд рангу нічого не перезаписує.
- Перевіряються права автора, права бота й ієрархія ролей.
- Тимчасові timeout виконуються Discord; власні відкладені задачі переживають рестарт.
- Музичні черги, гучність, задачі та блокування окремі для серверів.
- Пошук/FFmpeg мають квоти, timeout і гарантоване завершення.
- Немає глобального синхронного мережевого виклику в циклі Discord.
- Секрети не потрапляють у Git і логи.
- Одне сімейство Discord-бібліотеки й відтворювані залежності.
- Запуск не перевстановлює залежності й не змінює реєстр Windows.

## Що ще потрібно до великого публічного запуску
PostgreSQL під навантаженням; тривалі тести; резервне відновлення;
політика зберігання/видалення даних; Discord verification/intents;
метрики p95/p99, RAM і rate limits; розподіл shard-ів між процесами;
окремі музичні вузли; вебпанель з OAuth2 і перевіркою доступу до кожного guild.

SQLite і 1000 синтетичних guild ID — локальний тест, не доказ місткості тисяч
активних Discord-серверів. Мільйонна аудиторія і SLA 99.9% не можуть бути
гарантовані лише переписуванням коду.
