# Музичний комплект для Windows ZIP

Розпакуйте весь ZIP гілки `main`, відкрийте
`YEBOYBot.cmd` і виберіть початкове встановлення. Панель виконує чотири етапи:

1. Знаходить Python 3.12 x64; за відсутності встановлює через WinGet.
2. Готує `.venv-v2` та Python-бібліотеки.
3. Використовує підтверджені системні FFmpeg/Deno за вашим вибором або
   завантажує лише потрібні портативні програми; готує `options.ini`.
4. Перевіряє готовність і відкриває панель керування.

Звичайний GitHub **Code → Download ZIP** містить код завантажувача.
Якщо сумісні системні FFmpeg ≥9.0.2 та Deno ≥2.9.8 знайдені, майстер показує
шлях і версію кожного, після чого пропонує **[1] ТАК** (використовувати з ПК)
або **[2] НІ** (локальний комплект у папці бота). Варіанти незалежні:
можна обрати зовнішній FFmpeg і локальний Deno. Коли сумісної копії немає,
пропонується локальна. Відповідь **[0]** скасовує підготовку до pip/venv.

Звичайний Source ZIP не містить бінарники. Якщо потрібні **обидві локальні**
програми, архіви потребують приблизно 158 МБ трафіку; якщо одну — лише її
архів; якщо обидві зовнішні — їхні архіви не завантажуються.
Інтернет усе одно може бути потрібний для Python та бібліотек у `.venv-v2`.
FFmpeg/Deno не потребують окремого інсталятора, прав адміністратора або зміни PATH.

## Готовність після встановлення

У новій `.env.v2` встановлено `ENABLE_MUSIC=true`. Токен і сторонні
налаштування зберігаються. Для зміни джерел FFmpeg/Deno зупиніть бота
через **[3]**, відкрийте майстер **[19] → [1]** і виберіть програму.
Для підготовки музики без зміни попереднього вибору використовуйте **[20] → [1]**.
Новий майстер записує лише шляхи `FFMPEG_PATH` і `DENO_PATH` після
успішної перевірки; [20] не перезаписує ваш вибір.
Для підготовки програм бот має бути зупинений.

Після підготовки введіть власний Discord-токен та ID сервера через [12],
налаштуйте синхронізацію команд і запустіть бот через [1]. Приєднайтеся до
голосового каналу й виконайте `/music play query:назва пісні`.
Права Discord, доступність YouTube та власні Spotify API credentials не можуть
бути замінені встановленням програм. Spotify-трек відтворюється через пошук
відповідника; це не пряме відтворення аудіо Spotify.

## Програми та походження

| Компонент | Зафіксована версія | Локальний шлях |
|---|---|---|
| FFmpeg, Gyan Essentials x64 | 9.0.2 | `bin/ffmpeg/ffmpeg.exe` |
| Deno Windows x64 | 2.9.8 | `bin/deno/deno.exe` |

Джерела: [Gyan FFmpeg release](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.2)
та [Deno release](https://github.com/denoland/deno/releases/tag/v2.9.8).
Повні URL, розміри та SHA-256 зафіксовано в `tools/portable_media.py`.
**Зовнішні** програми не отримують локальних хешів: вони перевіряються
за версією, розташуванням і запуском, після явної згоди користувача.
На наступному встановленні вибір перевіряється ще раз. Коли зовнішня
програма зникла або більше не сумісна, інсталятор зупиняється, не
встановлює непогоджений замінник і пропонує змінити вибір через [19].
Усі файли вихідних архівів, включно з наявними ліцензійними файлами, зберігаються
після розпакування. Завантажувач не вимикає перевірку HTTPS-сертифікатів.

Перед запуском перевіряються розмір і SHA-256 архіву, допустимість шляхів ZIP
та відповідь програми на запит версії. Повторна підготовка перевіряє локальний
файл і версію; якщо все справне, мережа не потрібна. Незнайома папка
`bin/ffmpeg` або `bin/deno` не перезаписується. Несправна власна копія зберігається
як `*.previous-*` перед заміною, лише після успішної перевірки нової копії.

## Якщо підготовка зупинилася

Консоль показує етап збою (наприклад, «розпакування ZIP», «запуск програми»
або «публікація програми»), категорію помилки й код ОС, якщо він доступний.
Необхідні лише безпечні повідомлення: особисті шляхи, вміст файлів і токени
не виводяться. Для локального FFmpeg скорочено шляхи тимчасових каталогів
і спільну кореневу папку архіву; інсталяція все одно зберігає всі ліцензії
та супровідні файли.

Якщо архів повністю завантажений і SHA-256 пройшов, але розпакування або
перевірка завершилися помилкою, перевірений ZIP зберігається в `bin` як
`.media-verified-*.zip`. Наступне встановлення перевірить хеш повторно
та використає цей ZIP без нового завантаження 114 МБ; після успішного
встановлення кеш прибирається. Неповний або невірний архів не зберігається
як довірений і не запускається.

Якщо встановлення зупинилося на етапі **«запуск програми», код ОС 5**,
це означає, що Windows відмовила у виконанні `ffmpeg.exe`, а не що
ZIP пошкоджений. Відкрийте **Безпека у Windows → Захист від вірусів
і загроз → Журнал захисту** та перевірте події на час запуску. Далі
відкрийте **Перегляд подій → Журнали програм і служб → Microsoft →
Windows → CodeIntegrity → Operational** (подія **3077**) і
**AppLocker → EXE and DLL** (подія **8004**). Не кожна відмова дає
подію в обох журналах. Ці події вказують на блокування політиками
запуску, але не гарантують, що причина саме в них.

Не вимикайте антивірус, Smart App Control або AppLocker для обходу
помилки. Для керованого ПК зверніться до адміністратора. Майстер
`YEBOYBot.cmd → [1]` самостійно повторно використовує підтверджені
FFmpeg/Deno з каталогу WinGet (навіть якщо поточний PATH застарів).
Коли Windows повертає **код 5 саме під час запуску локальної програми**,
цей же майстер може автоматично встановити офіційний пакет через WinGet
для поточного користувача, перевірити абсолютний шлях і продовжити.
Згода на цей резервний сценарій пояснюється в початковому меню [1];
без неї WinGet для медіапрограм не запускається. Під час неінтерактивних
відновлень системні пакети не встановлюються.
Політика Windows може забороняти і системну копію.

Якщо Windows повідомляє про довгий шлях, використайте короткий шлях
на кшталт `C:\\YEBOYBot`. Якщо відмовлено в доступі, перевірте історію
блокувань у Захисті Windows і права на папку; не вимикайте захист.
При помилці SHA-256 не змінюйте контрольні суми. Токен і дані бота зберігаються.

Для Linux використовуйте штатний менеджер пакетів для FFmpeg, Deno та libopus.
Автоматичний портативний комплект призначено для Windows x64.
