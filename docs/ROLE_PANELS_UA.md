# Панелі самостійного вибору ролей

Core V2 має `/role-panel create`, `/role-panel list` і `/role-panel remove`.
Для появи нових команд виконайте синхронізацію через `YEBOYBot.cmd` → [11]
та перезапуск → [2]. Спочатку перевірте модуль на тестовому сервері.

## Використання

1. Створіть звичайну роль, наприклад «Новини». Розмістіть її нижче ролі бота й
   власної найвищої ролі. Не надавайте їй адміністративних чи модераційних прав.
2. Виконайте `/role-panel create channel:#ролі role:Новини`.
3. У текстовому каналі з'явиться повідомлення з кнопками **Отримати роль** та
   **Зняти роль**. Відповідь на натискання бачить лише цей учасник. Повторне
   отримання вже наявної ролі або зняття відсутньої не змінює стан повторно.
4. `/role-panel list page:1` показує ID активних панелей лише поточного сервера.
   Є до 50 панелей на сервер, по 10 на сторінці.
5. `/role-panel remove panel_id:…` відкликає панель. Старе повідомлення залишається,
   але його кнопки більше не видають і не знімають ролі. Вже видані ролі залишаються;
   за потреби адміністратор видаляє їх окремо.

Налаштування зберігаються в наявній таблиці Core V2, без нової міграції. Кнопки
працюють після перезапуску завдяки реєстрації DynamicItem; завантажувати всі панелі
в пам'ять або надсилати повідомлення знову не потрібно. Members Intent для цих
кнопок не потрібний: поточний учасник перевіряється через Discord REST.

## Дозволи й перевірки

Створення, список і відкликання потребують **Manage Guild та Manage Roles**.
Створення також потребує View Channel/Send Messages для автора й бота в обраному
каналі. Для натискання потрібен доступ до каналу; боту потрібні Manage Roles і
роль вище тієї, яку він видає. Новачок із незавершеною Membership Screening
отримує відмову, щоб видача ролі не обходила перевірку Discord.

На кожну операцію бот читає свіжі ролі й учасників через REST, не довіряючи лише
кешу події. Перед видачею/зняттям перевіряє:

- належність панелі, повідомлення, каналу й учасника одному серверу;
- що повідомлення створив саме цей бот;
- що роль не @everyone, не managed/integration, нижча за роль бота;
- відсутність привілейованих прав ролі, зокрема в channel overwrites;
- для створення — що роль також нижча за роль адміністратора (крім власника).

Роль із правами керування сервером, ролями, каналами, повідомленнями, подіями,
модерації чи іншими правами зі спільного переліку безпеки не допускається.
При зміні ролі на привілейовану вже опублікована панель відмовляє у дії.
Власний дозвіл View Channel для обмеженої кімнати не заборонений: адміністратор
повинен свідомо обирати, які канали відкриває самостійно отримувана роль.

## Межі й відновлення

Це одна роль і дві кнопки на панель, без select menus, реакцій, груп
взаємовиключення або кількох ролей в одній кнопці. Не повна рівність із ProBot.
Кнопки не створюють записів модерації, але Discord-запит містить ID панелі в
причині для Audit Log. Повідомлення не пінгує роль або учасників.

Операції одного сервера серіалізуються в одному процесі: новий запит під час
попереднього отримує повідомлення «спробуйте пізніше», черга очікувачів не росте.
Одночасно допускається до 32 операцій різних серверів; одна операція обмежена
20 секундами, натискання учасника — раз на 2 секунди, кеш cooldown — 10000 ключів.
Перед зміною ролі потрібні кілька REST-запитів, включно з перевіркою каналів;
це безпечний початковий варіант, а не benchmark великого навантаження.

Якщо Discord явно відхилив публікацію через Forbidden/NotFound, запис панелі
відкликається. При таймауті чи невизначеній HTTP-помилці запис залишається:
перевірте канал і `/role-panel list`, перш ніж створювати ще одну панель;
зайву панель відкличте. При невизначеній видачі/знятті спочатку перевірте свої
ролі. Автоматичного повтору з невідомим результатом немає.

Discord і SQL не утворюють спільну транзакцію: зміна прав між REST-перевіркою та
дією все ще можлива. Відкликання серіалізується з кліками лише в цьому процесі;
запускайте один керований процес цієї інсталяції. Зупинка модуля скасовує його
активні задачі, але не відкочує уже прийнятий Discord-запит. Якщо безпечна роль
згодом стала небезпечною, зніміть її адміністративними засобами: панель блокує
і видачу, і зняття такої ролі.

## Ручний сценарій приймання

Створіть панель → отримайте/повторно отримайте/зніміть роль → перезапустіть бот
і повторіть → відкличте панель та перевірте старі кнопки. Окремо перевірте втрату
Manage Roles у бота, підняття ролі вище бота, додавання Manage Messages у
перевизначення каналу, користувача з pending Screening і спробу керування без
потрібних прав. Автоматичні тести використовують реальні SQLite й моделі
Discord SDK із підміненою мережею; вони не замінюють цей живий сценарій.
