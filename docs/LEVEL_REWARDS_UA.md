# Ролі за рівні — Core V2

Оновлення 31.10.2026 додає постійні правила нагород за **окремі рівні чату й голосу**.
Вони використовують ті самі пороги, що й `/rank`; XP і наявні ролі не скидаються.
Правила зберігаються в SQL і переживають перезапуск. За замовчуванням правил немає.

## Оновлення наявної інсталяції

Ця версія потребує **схеми БД 3**. Не запускайте новий код поверх схеми 1/2
без міграції. Нову порожню БД бот створює одразу у версії 3.

1. Зупиніть усі копії бота, які використовують цю БД; у `YEBOYBot.cmd` — **[3]**.
2. Для SQLite відкрийте **[21]**, перевірте план і введіть `МІГРУВАТИ`.
   Лаунчер створює й перевіряє резервну копію перед змінами.
   Для PostgreSQL використайте **[23] → [1] план → [3] міграція**;
   потрібні сумісні `pg_dump` і `pg_restore`.
3. Виконайте **[4]** — діагностику, **[11]** — синхронізацію команд,
   потім запустіть бот через **[1]**. Перевірте `/help` → «Ранг і XP» та `/modules`.

Перехід 2→3 додає таблицю `v2_level_rewards`. Перехід 1→3 спершу виконує
існуючу міграцію 1→2. Автоматичного downgrade немає: для повернення потрібні
відповідний код і перевірена попередня копія. Деталі: [міграції](MIGRATIONS_UA.md).

## Команди

| Команда | Дія |
|---|---|
| `/level-reward set kind:text level:5 role:@Активний` | Нагорода за 5-й рівень чату |
| `/level-reward set kind:voice level:3 role:@Співрозмовник` | Нагорода за 3-й рівень голосу |
| `/level-reward list` | Переглянути правила цього сервера |
| `/level-reward remove kind:text level:5` | Видалити правило; вже видані ролі залишаються |
| `/claim-rewards` | Отримати власні зароблені ролі за поточними правилами |

Керування правилами потребує **Manage Guild і Manage Roles**. Боту для видачі
потрібен **Manage Roles**, а його найвища роль має бути вище нагороди.
Роль нагороди має бути нижчою за роль адміністратора, який її налаштовує
(власник сервера має виняток лише для власної ієрархії).
Відповіді приватні; повідомлення не викликають згадок.

Максимум **25 правил на сервер**, рівні **2–1000**. Для однієї пари
«тип XP + рівень» зберігається одна роль; повторний `set` замінює правило.
Стара видана роль при заміні не знімається.

## Пороги та видача

Рівень починається з 1. Для рівня `L` потрібно:

| Тип | Потрібно XP | Приклади |
|---|---|---|
| Чат | `100 × (L − 1)²` | рівень 2: 100; рівень 5: 1600 |
| Голос | `50 × (L − 1)²` | рівень 2: 50; рівень 3: 200 |

Після успішного нарахування XP бот запускає обмежену перевірку нагород.
Видаються всі зароблені ролі за наявними правилами, без зняття попередніх.
Повторна перевірка не виконує зайву видачу ролей, які вже присутні.
`/levels enabled:false` припиняє нову видачу; наявний XP і ролі зберігаються.

Нове правило не запускає масову перевірку всіх учасників. Уже зароблену нагороду
можна отримати наступною придатною активністю або через `/claim-rewards`.
Ця ж команда допомагає після перезапуску, перевантаження чи тимчасової помилки Discord.
При непідтвердженому результаті перевірте ролі; повторна спроба знову читає
актуальний стан учасника.

## Перевірки та межі

- Права, ролі, учасник і привілейовані дозволи ролі в каналах перевіряються через REST.
  Адміністративні, керовані інтеграціями та `@everyone` ролі не видаються.
- Боти та учасники, які ще проходять Membership Screening, нагород не отримують.
- Дані різних серверів ізольовані. Команди налаштування й видача серіалізовані
  в межах сервера в одному процесі бота. Не запускайте кілька незалежних
  процесів для того самого сервера: ця серіалізація не є розподіленим блокуванням.
- Якщо одна із зароблених ролей стала небезпечною або була видалена, перевірка
  блокує весь набір до першої видачі. Адміністратор має виправити чи видалити це правило.
- Видача має обмеження паралельності й часу. При зайнятому сервері або загальному
  ліміті автоматична спроба може бути пропущена; нескінченної черги немає.
- Discord і SQL не утворюють спільної транзакції. Права можуть змінитися між
  перевіркою й запитом; серія кількох видач може завершитися частково.
  Вимкнення XP зупиняє наступні видачі, але вже відправлений Discord-запит
  може завершитися після перемикання.
- Видалення правила не відкликає вже надані ролі. Якщо потрібне зняття ролі,
  адміністратор робить це окремо. Ексклюзивні нагороди й заміна нижчої ролі
  вищою поки не реалізовані.
- Винятки XP для окремих каналів/ролей та окреме вмикання текстового й голосового
  XP залишаються наступним етапом. Цей реліз додає саме нагороди.

## Перевірка на тестовому Discord-сервері

1. Створіть звичайну роль нижче ролей бота й адміністратора, без дозволів модерації.
2. Налаштуйте поріг, досягнутий вашим тестовим учасником згідно з `/rank`.
3. Від учасника виконайте `/claim-rewards`: роль має з'явитися; повтор не має її зняти.
4. Перезапустіть бот і перевірте `/level-reward list` та повторне отримання.
5. Змініть роль на привілейовану й перевірте, що нова видача блокується.
6. Видаліть правило: старі ролі залишаються, нові учасники його більше не отримують.

Локальні тести використовують ізольовані БД та підмінений Discord HTTP.
Вони не підтверджують роботу на вашому сервері без цього окремого сценарію.
