# YEBOYBot та ProBot: перевірка й розвиток — 29.10.2026

База перевірки: `feature/core-v2`, коміт `0698223`. Ця гілка випереджала `main` на 59 комітів. Зміни підготовлено окремо у `improvement/probot-readiness`; вони не означають запуск на Discord чи злиття в main.

## Висновок

ProBot сильніший широтою готового продукту і зручністю адміністрування: вебпанель, настроювані правила AutoMod, рольові нагороди, self-roles і тікети. YEBOYBot має основу для власного продукту: self-hosting, відкритий код для власника, український CMD Control Center, SQLite/PostgreSQL, backup/restore, окремий текстовий і голосовий XP та контрольовані модераційні справи. Це переваги контролю й адаптації, а не доказ кращого uptime, швидкості чи захисту порівняно з ProBot.

## Виправлені проблеми

1. **Timeout/untimeout використовували старі кешовані права та не мали стійкого захисту від повтору запиту.** Переведено на ModerationService: свіжа перевірка учасників/ролей, запис справи до API, повтор не надсилає другу дію. Невизначений мережевий результат залишається pending для перевірки. Причина timeout тепер максимум 470 символів: тривалість входить у збережений запит. Discord API не дає атомарної транзакції разом із локальною БД.
2. **XP після імпорту максимальних значень міг переповнювати bigint або втрачати точність у SQLite.** Лічильник насичується на 2^63−1; cooldown зберігається.
3. **Аварійний працівник нагадувань міг залишати нескінченну кількість спроб.** Прострочена п'ята оренда переходить у failed; активні оренди й інші сервери не зачіпаються.
4. **У Git зберігалися згенеровані pyc.** Вилучено дев'ять кеш-файлів з індексу; вихідний legacy-код збережено.

## Нові завершені сценарії

- `/community welcome channel:#канал`: текстове привітання. Без channel — вимкнення.
- `/community autorole role:Учасник`: непривілейована роль після Membership Screening. Без role — вимкнення.
- `/community logs channel:#журнал`: метадані подій без текстів приватних повідомлень. Без channel — вимкнення.
- `/automod enabled:true`: понад 5 повідомлень за 5 секунд або щонайменше 8 різних згадок. Видаляється лише нове повідомлення; timeout/ban не застосовуються. `false` вимикає.
- `/help` має розділ «Спільнота»; `/modules` розрізняє підключені й майбутні модулі.

Автоматичні дії вимкнено за типовими налаштуваннями. Якщо раніше вручну заповнювали неактивні поля automod/welcome_channel/autorole/log_channel у БД, після цього оновлення вони почнуть діяти: перевірте їх перед запуском.

## Межі перевірки

Перевірено код Core V2, пов'язаний lifecycle/БД, нові модулі та регресії наявного suite. Не виконано повний незалежний аудит всього legacy, формальну верифікацію, пентест живого сервера, тестування Discord з вашим токеном чи production load test. Pattern-скан поточних tracked текстових файлів не знайшов приватних ключів, GitHub/Discord токенів; це не повний аудит історії Git і не доказ відсутності всіх секретів. `pip check` перевіряє сумісність пакетів, а не CVE.

Community пропускає події понад ліміт одночасної роботи, не має стійкої черги/replay і не є повним audit ledger. Авторолі перевіряють кеш ролей; особа, яка їх налаштувала, не зберігається. Members Intent вмикає кеш новоприєднаних учасників для Screening, що збільшує пам'ять. Антиспам обмежує частоту видалень; частина флуду може залишитися. Немає фільтрів змісту, редагувань, anti-raid чи індивідуальних порогів. Бот не став повним аналогом ProBot.

## Наступні етапи з критеріями приймання

1. **Надійність релізу:** Windows і PostgreSQL CI, ручний тест Discord на окремому сервері, перевірка backup/restore та зупинки. Критерій: усі середовища підтверджені, відмова прав не створює несанкціонованих дій.
2. **Повноцінний AutoMod:** версійовані правила/винятки, observe-only, Discord native AutoMod для слів/URL, причини спрацювання та приватний журнал. Критерій: тести обходів, tenant isolation, bounded memory, без каральної дії у dry-run.
3. **Self-roles і XP-нагороди:** стійкі компоненти після рестарту, safe-role перевірки при кожному натисканні/нагороді, голосові нагороди без потреби писати в чат. Критерій: конкурентні кліки не видають зайві ролі, змінена привілейована роль відхиляється.
4. **Тікети:** приватні канали, claim/close, ліміти, безпечні transcripts, контроль строків збереження. Критерій: іншій команді/серверу недоступні дані; рестарт не губить стан.
5. **Вебпанель:** Discord OAuth2, перевірка Manage Guild на кожному записі, CSRF, безпечні cookie, server-side tenant scope. До цього не виставляти локальну БД/токен в інтернет. Python залишається ядром; TypeScript потрібний лише для реального фронтенда, нові мови самі по собі не покращують бота.
6. **Експлуатація:** метрики затримки, частоти 429/помилок, черг, пам'яті та часу відновлення. Порівняння з конкурентом проводити однаковими сценаріями, без вигаданих uptime чи кількості серверів.

Взяти саме гілку з цими змінами, зробити backup через `YEBOYBot.cmd` → [7]. Для встановлення/відновлення бібліотек [24], для налаштувань [12], діагностики [4]. Для нових slash-команд потрібна синхронізація через [11] і перезапуск [2]; спочатку використайте тестовий сервер. Привітання/автороль потребують `ENABLE_MEMBERS=true` у `.env.v2` та Server Members Intent у Discord Developer Portal. Токен нікому не надсилати.

Далі: налаштувати три `/community` команди й `/automod`; перевірити звичайне повідомлення, шосте швидке повідомлення, втрату Manage Messages, новачка з pending screening, відмову небезпечній ролі, вимкнення всіх опцій. Перезапустити бот і перевірити збережені налаштування. Наявні бази не видаляти й не створювати заново.

## Результат локальних перевірок

Linux, Python 3.12, окреме venv із зафіксованими requirements-dev: **2125 passed, 209 skipped** (26.51 с). Пропуски включають Windows і PostgreSQL/native-client сценарії, для яких тут немає потрібного середовища. Ruff, pip check і git diff --check успішні. Попередній прогін виявив застаріле очікування кількості slash-груп у тесті музики; оновлено очікування і перевірку реєстрації нових cog, потім повторено весь suite. Одне попередження: discord.py використовує audioop, deprecated у Python 3.12. Цільова версія проєкту залишається Python 3.12.

Не заявлено успіх нового Windows/PostgreSQL GitHub Actions або живого Discord до отримання їх результатів. Незалежна повторна перевірка нових модулів не знайшла блокуючих дефектів прав; залишила два follow-up: in-flight читання кешу може ненадовго повернути попереднє значення AutoMod після вимкнення (TTL 15 с), а вже запущені Community-події не дренуються окремо перед закриттям БД. Миттєва зупинка й гарантована доставка не обіцяються.
