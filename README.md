# YEBOYBot

YEBOYBot — Discord-бот для керування серверами та автоматизації роботи спільнот.

Мета проєкту — створити надійного, масштабованого та зручного бота з функціями модерації, налаштуваннями для різних серверів і майбутньою вебпанеллю керування.

> Проєкт перебуває в активній розробці. Документація щодо функцій, встановлення та запуску доповнюватиметься в міру реалізації.


**Для Core V2 використовуйте `YEBOYBot.cmd`. Старі функції доступні через [22]
або окремий `run.bat`: вони встановлюються лише в `.venv-legacy`, без змін реєстру
й глобальних пакетів.** [Інструкція legacy](docs/LEGACY_LAUNCHER_UA.md).

На Windows відкрийте `YEBOYBot.cmd`, виберіть **[12] Початкове налаштування**,
введіть токен приховано та ID тестового сервера, потім **[1] Запустити**.
Потрібен Python 3.12 із Python Launcher або доступний як `python`; середовище `.venv-v2` встановлюється автоматично.
Повна інструкція: [Windows CMD](docs/WINDOWS_CMD_LAUNCHER_UA.md).
Core V2 — тестова версія; реальний Discord-сценарій власника ще потребує перевірки.


Діагностика через меню: **[4]** — локальні перевірки, **[18]** — JSON-звіт без секретів.

Резервування SQLite: **[7]** створює копію з SHA-256, **[8]** відновлює після
підтвердження, **[20]** перевіряє копії та переносить старі в архів без видалення.
Копії містять дані серверів і не шифруються; зберігайте їх приватно.

Автозапуск Windows налаштовується окремо через **[15]** і лише після підтвердження:
бот запускається після входу поточного користувача, без збереження пароля.

Core V2 зупиняє клієнт при втраті heartbeat-контролю та відхиляє несумісну
схему БД до її зміни. Деталі й порядок діагностики — в інструкції Windows CMD.

Наявна SQLite v1 після оновлення потребує явної міграції: **[3] → [21] →
МІГРУВАТИ → [4] → [1]**. Нова БД створюється одразу зі схемою v2.
[Міграції та відновлення](docs/MIGRATIONS_UA.md). Для стандартної PostgreSQL v1:
**[3] → [23] → [1] план → [3] міграція** з native backup перед DDL.
**[23] → [4]** відновлює власну Core-копію лише в окрему порожню БД.
Потрібні штатні pg_dump/pg_restore; автоматичної зміни схеми під час login немає.
[Інструкція PostgreSQL](docs/POSTGRES_RECOVERY_UA.md).

Core V2 має 16 slash-команд, зокрема `/kick`, `/ban`, `/unban` і `/modhistory`:
свіжі перевірки прав/ролей, запис справи до API та приватна історія результатів.
Ban зберігає повідомлення, unban приймає ID колишнього учасника.
