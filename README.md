YEBOYBot — Discord-бот для керування серверами та автоматизації роботи спільнот.

Мета проєкту — створити надійного, масштабованого та зручного бота з функціями модерації, налаштуваннями для різних серверів і майбутньою вебпанеллю керування.

> Проєкт перебуває в активній розробці. Документація щодо функцій, встановлення та запуску доповнюватиметься в міру реалізації.


**Для Core V2 використовуйте `YEBOYBot.cmd`. Старі функції доступні через [22]
або окремий `run.bat`: вони встановлюються лише в `.venv-legacy`, без змін реєстру
й глобальних пакетів.** [Інструкція legacy](docs/LEGACY_LAUNCHER_UA.md).

На Windows 10/11 x64 розпакуйте весь проєкт і відкрийте `YEBOYBot.cmd`.
На новому ПК з'явиться панель **[1] Встановити все для Core V2 / відновити бібліотеки**:
після вибору вона встановить відсутній Python 3.12 x64 через WinGet, підготує
`.venv-v2` та перевірить бібліотеки. Вводити команди Python чи pip не потрібно.
Потрібні інтернет і Windows App Installer (WinGet); якщо його немає, панель дає
офіційні посилання для встановлення. [Сценарій чистого ПК](docs/CLEAN_PC_SETUP_UA.md).

Після успішного встановлення у головному меню виберіть **[12] Початкове налаштування**,
введіть токен приховано та ID тестового сервера, потім **[1] Запустити**.
Наявна справна копія одразу відкриває головне меню; повторна панель встановлення
доступна через **[24]**. Повна інструкція: [Windows CMD](docs/WINDOWS_CMD_LAUNCHER_UA.md).
Core V2 — тестова версія; реальний Discord-сценарій власника ще потребує перевірки.


Діагностика через меню: **[4]** — локальні перевірки, **[18]** — JSON-звіт без секретів.

Резервування SQLite: **[7]** створює копію з SHA-256, **[8]** відновлює після
підтвердження, **[20]** перевіряє копії та переносить старі в архів без видалення.
Копії містять дані серверів і не шифруються; зберігайте їх приватно.

Автозапуск Windows налаштовується окремо через **[15]** і лише після підтвердження:
бот запускається після входу поточного користувача, без збереження пароля.

Core V2 зупиняє клієнт при втраті heartbeat-контролю та відхиляє несумісну
схему БД до її зміни. Деталі й порядок діагностики — в інструкції Windows CMD.

Наявна SQLite v1/v2 після оновлення потребує явної міграції: **[3] → [21] →
МІГРУВАТИ → [4] → [1]**. Нова БД створюється одразу зі схемою v3.
[Міграції та відновлення](docs/MIGRATIONS_UA.md). Для стандартної PostgreSQL v1/v2:
**[3] → [23] → [1] план → [3] міграція** з native backup перед DDL.
**[23] → [4]** відновлює власну Core-копію лише в окрему порожню БД.
Потрібні штатні pg_dump/pg_restore; автоматичної зміни схеми під час login немає.
[Інструкція PostgreSQL](docs/POSTGRES_RECOVERY_UA.md).

Core V2 має команди `/kick`, `/ban`, `/unban` і `/modhistory`:
свіжі перевірки прав/ролей, запис справи до API та приватна історія результатів.
Ban зберігає повідомлення, unban приймає ID колишнього учасника.
[Налаштування й межі модерації](docs/MODERATION_UA.md).

`/warn` перевіряє актуальні права й ролі через Discord REST та атомарно
зберігає локальне попередження. Повтор того самого запиту не додає другий запис
і не відновлює відкликане попередження. `/warnings` показує приватний обмежений
список; повні причини зберігаються в БД.

[Карта коду та архітектури](<Код структура.txt>) описує Core V2, Control Center,
legacy, точки входу, дані й навігацію документацією.

`/clear` показує приватне підтвердження для обмеженого списку повідомлень;
`/clear-status` перевіряє власний збережений запит без повторного видалення.
[Очищення з підтвердженням і його межі](docs/CLEAR_UA.md).

Графічний `/rank` знову використовує ваші `DLC/rank_background.png` і `gg.png`: аватар,
іконка сервера, окремий текстовий/голосовий XP, рівні й прогрес. Голосовий XP
нараховується за повні хвилини спільної придатної присутності, без прослуховування.
**[26]** переносить старий JSON XP у SQLite після підтвердження та backup,
**[25]** налаштовує музику й `options.ini`, FFmpeg і Deno. Добровільна група
`/music` додає дев'ять підкоманд: черги серверів, автоплейлист, пріоритет замовлень,
ручну паузу з відновленням і гучність поточної сесії.
[Ранг, XP, музика та покрокове налаштування](docs/RANK_MUSIC_UA.md).

У `/leaderboard` можна вибрати `xp_type`: **Загальний**, **Чат** або **Голос**.
Без параметра лишається сума чату й голосу. Окремі рейтинги відповідають
місцям на PNG-картці `/rank`; за однакового XP вище профіль із меншим Discord ID.
Сума й порядок зберігають точність для великих допустимих лічильників.
Після оновлення параметра потрібні sync через **[11]** і restart **[2]**.
[Вибір рейтингу](docs/RANK_MUSIC_UA.md#окремі-рейтинги-чату-й-голосу).

Музичний плеєр показує в `/music queue` українські стани й безпечні підказки
для мережі/TLS/джерела. Навмисна зупинка блокує відкладене автопідключення;
неправильне посилання не створює voice-з'єднання. [Діагностика й зупинка](docs/RANK_MUSIC_UA.md#діагностика-джерел-і-надійна-зупинка--28102026).

Якщо локальне від'єднання або очищення аудіо не підтверджено, власна музична сесія
залишається під контролем і блокує нові підключення. `/music stop` повідомляє
про незавершену зупинку; повторна команда перевіряє ту саму сесію.
`/music queue` і `/modules` показують цей стан. Повільне отримання треку більше
не приховує миттєве завершення відтворення й не скидає паузу між спробами.
[Відновлення музичного плеєра](docs/RANK_MUSIC_UA.md#непідтверджена-зупинка-та-повторна-спроба).

`/music pause` і `/music resume` керують наявною сесією для користувача з
дозволом «Керувати сервером» у тому самому голосовому каналі. Ручна пауза
не скасовується приходом людей; відновлення не обходить AutoPause порожнього
каналу. Налаштування діє до завершення сесії. Після оновлення синхронізуйте
нові підкоманди через **[11]**, потім перезапустіть через **[2]**.
[Пауза, відновлення й перевірка стану](docs/RANK_MUSIC_UA.md#ручна-пауза-й-відновлення).

`/music volume percent:0..100` змінює гучність наявної сесії; без числа показує
поточний стан. Потрібні «Керувати сервером» і той самий голосовий канал.
Значення 0 вимикає звук без додавання паузи; наявна пауза залишається.
Під час відтворення час треку й черга продовжуються.
Значення діє для поточного й наступних треків цієї сесії, після нової сесії або
перезапуску знову читається `DefaultVolume` з INI. Команда не записує INI чи БД.
Для нової підкоманди: синхронізація обраної області через **[11]**,
потім перезапуск **[2]**.
[Гучність, стани PCM і межі перевірки](docs/RANK_MUSIC_UA.md#гучність-музичної-сесії--29102026).

`/help` відкриває приватну українську довідку з розділами й сторінками.
`/modules` показує поточний стан модулів сервера, вимкнені можливості та
невідомі стани при збоях. Команди лише читають дані.
[Довідка, стан модулів і синхронізація](docs/GUIDE_UA.md).
